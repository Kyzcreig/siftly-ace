# Deterministic Digest Scoring — Senior Review (Pass 1)

## Verdict
BLOCK / **APPROVE WITH CHANGES**

## Critical Blockers

1. **§6.2 + §7 — "≥ current ranking" is not objectively measurable as written; shadow mode cannot gate cutover.** The acceptance criterion is "shadow data shows the deterministic ranking is ≥ the current one on known-good/known-bad items," but the spec defines **no labeled set, no metric, and no pass threshold**. "≥" over a ranking needs a concrete comparator (Kendall-τ vs. a frozen gold set? top-5 set-overlap? zero known-bad in TOP, all known-good above ALSO_GATE?). Without a pre-registered gold set + numeric threshold, "the data says it's better" collapses to eyeballing — exactly the subjective calibration this spec exists to kill. **This is the load-bearing gate for a daily digest cutover and it's undefined.**

2. **§4 + §6.3 — double-scoring / contradiction risk between the new BASE table and the surviving select_digest.py guards is unspecified.** The spec says guards "become inputs" (§4.4) but §6.3 also says "keep the existing guards as backstops for one release." That means for ≥1 release **two scoring authorities run simultaneously**: `score_digest.py` produces `final` from labels+engagement, AND `select_digest.py`'s `score_item()` still computes `base + pf + boost` then `low_reach_cap`. The spec never says which `final` the gate (TOP_GATE=83/ALSO_GATE=77) consumes, whether the old `compute_boost`/`pf_delta` is double-applied on top of the new `author_tier_points`, or whether `low_reach_cap` re-caps an already-engagement-scored item. **A tracked-project post could get +8 from `author_tier_points` AND +8 from `compute_boost` = +16 double-count.** This is a silent-regression generator.

3. **§4.1 — gate constants are calibrated against the OLD score distribution; the new BASE table produces a different distribution but TOP_GATE/ALSO_GATE are unchanged.** Today base≈80 is the model's flat-rate floor and gates sit at 83/77. After cutover, `launch×actionable_now=70` is the *ceiling* of the base table, and a typical good post is `field_report×reference` (unspecified, but clearly <70) + engagement + author. **Nothing in the spec re-derives TOP_GATE/ALSO_GATE against the new score range.** If the new distribution centers at 55–75, the existing 83/77 gates either pass almost nothing (empty digest — load-bearing daily breaks) or everything (inflation returns). The forced-distribution rule (MAX_GE_90=2, MAX_EQ_100=1) is also silently unreachable if nothing clears 90.

4. **§3 + §4 — no fail-open/fail-closed policy for malformed/missing labels.** The whole base score now depends on the model emitting a valid `(content_type, actionability)` enum pair. The spec never says what happens when the model returns `content_type="launch "` (trailing space), an out-of-enum value (`"announcement"`), a missing field, or invalid JSON. With the old path, a parse failure degraded to a model-authored number (bad but bounded). Now a `KeyError` on `BASE[content_type, actionability]` either crashes the digest (fail-closed → no #daily digest ships, the worst load-bearing outcome) or silently defaults to 0 (fail-open-to-discard → good posts vanish). **Neither is acceptable undefined.**

5. **§4.2 — log-curve engagement is gameable and the spec acknowledges no mitigation.** `K*log10(1+likes+rt)` capped at +15 means the cap is reached at a fixed engagement; below it, the marginal cost of faked engagement is highest at low counts (0→10 likes buys more points than 1000→10000). Bot rings and reply-spam farms that buy 50–200 likes land in the steep part of the curve and convert cheap purchased engagement into real score — and `low_reach_cap` (the current defense) is explicitly being "obviated" (§4.3). **The spec removes the engagement-gaming defense and replaces it with an engagement-driven score, with no anti-gaming term** (no velocity check, no engagement/follower ratio, no author-age signal).

## Required Changes

1. **Pre-register the shadow-mode gold set + comparator BEFORE build.** Freeze a labeled set from the incident pools + a sampled N-day window (e.g. 200 items hand-labeled known-good / known-bad / neutral). Define the pass metric concretely: e.g. "**zero known-bad items in the TOP set AND every known-good item scores ≥ ALSO_GATE, across all N shadow days; AND top-5 set-overlap with the human-labeled ideal ≥ 0.8 (4/5)**." Cutover is blocked until that numeric bar is met. Add this to §7 as the literal acceptance text.

2. **Specify single-source-of-truth scoring during the backstop window.** During shadow + the one-release backstop, `score_digest.py` is the **only** authority that produces the `final` the gate consumes. Either (a) `select_digest.py`'s `score_item()` is rewired to consume `score_digest.py`'s `final` and apply *only* the gate/distribution/dedup logic (no second base+pf+boost), or (b) guards run in **assert-only/log-only** mode (compute, log disagreement, do not mutate score). Write the exact ownership boundary into §4.4 and §6.3. **No path may apply author/tracked boost twice.**

3. **Re-derive TOP_GATE / ALSO_GATE / forced-distribution against the new score range, as part of shadow mode.** Make the shadow artifact dump the new-score distribution; pick gates so the new digest produces the same *volume* (≈MAX_TOP top + MAX_ALSO also) on the incident pools as today. Treat the gates as tunables that ship WITH the cutover, not constants inherited blind. Add an explicit acceptance line: "new gates reproduce current digest cardinality on the shadow corpus."

4. **Define the malformed-label policy explicitly, fail-SAFE-not-silent.** On any out-of-enum/missing/invalid label: (a) coerce via a documented normalization (strip/lowercase/synonym map), (b) on still-invalid, assign a **defined safe-default label** (`content_type=opinion, actionability=context_only` → mid-low base, NOT 0, NOT crash), (c) **log the coercion to the debug dump and emit a counter** so silent mislabeling is visible. The digest must always ship; a malformed label must never crash the run or silently zero a good post. Add to §3/§4.

5. **Add an anti-gaming term before removing `low_reach_cap`.** Do NOT obviate the low-reach cap on the strength of the log curve alone. Either (a) **keep `low_reach_cap` as a hard floor-guard permanently** (the spec already hedges "keep the hard cap as a cheap floor-guard" — make that permanent, not "for one release"), or (b) add an engagement-quality signal (engagement/author-follower ratio, or author-tier gating on engagement points so unknown handles get a lower engagement cap). State which in §4.2/§4.3.

6. **Specify the BASE table in full, not by example.** §4.1 gives 4 illustrative cells; the model emits 9 content_types × 4 actionabilities = **36 cells**. Every cell must be enumerated and committed in the spec/file (with the selftest asserting monotonicity: `launch ≥ field_report ≥ opinion` within an actionability column). An under-specified table is where the next "why 80?" lives.

## Lens Notes
- **Product:** The #daily digest is load-bearing; a cutover that empties it (blocker 3) or crashes it (blocker 4) is a worse failure than today's inflation — fail-safe + cardinality-parity are non-negotiable.
- **Architecture:** Clean direction (classify vs. score), but two scoring authorities coexisting for a release (blocker 2) violates single-source-of-truth — must be assert-only or rewired, never dual-mutate.
- **Security:** Engagement-as-score without an anti-gaming term (blocker 5) hands a paid-likes lever directly into the digest; the log curve makes *cheap* engagement the most efficient.
- **DevOps-SRE:** No fail-open/closed policy (blocker 4) on a daily cron = either silent good-post loss or a dead digest; needs a defined safe-default + visible coercion counter routed to alerts.
- **Implementation:** BASE table specified by 4 examples (req-change 6) and gates inherited blind (blocker 3) will produce a built scorer whose behavior nobody can predict until shadow — front-load the full table + gate re-derivation.
- **QA:** "≥ current ranking" (blocker 1) is untestable without a frozen gold set + numeric metric; the acceptance checklist has unfalsifiable items — pre-register the gold set and the pass threshold.
