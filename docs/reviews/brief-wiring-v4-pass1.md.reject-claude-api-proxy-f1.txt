# Independent Senior Review (Opus)

## Verdict: APPROVE WITH CHANGES

## Critical Blockers (severity-ordered, cite section/evidence)

**B-1 — The 20-min wall budget vs. Reddit's measured 45–60s/IP spacing is an unresolved arithmetic collision the PRD waves at but never closes.** §5.2 measures "reliable 200s needed ~45-60s spacing per IP," then AC-15 prescribes "~5 of 9 subs" day-seeded. Do the math the PRD doesn't: 5 subs across 2 lanes = ~2.5 fetches/IP; at 45-60s/IP spacing that's 90-150s of pure Reddit sleep, serialized inside the *existing* gather+enrich+embed+export+score pipeline that already shares a 20-min `AbortController` budget (per the daily-ingest driver in AGENTS.md). The PRD never states (a) whether the two lanes fetch *concurrently* (if serialized, double the wall time), (b) what happens to the digest when the Reddit step alone eats 3-5 min and the AbortController fires mid-pipeline, or (c) that github+reddit+the 4 existing gatherers all fit. **The never-regress invariant (§3) is asserted, not proven against the wall-clock.** Required: an explicit per-source time box (Reddit step gets ≤N seconds, hard-capped independent of the global AbortController) + a dry-run wall-clock with all 6 sources, recorded *before* G1, not promised in AC-15's "dry-run wall-clock under budget."

**B-2 — D-4 ("first real fetch IS the health signal") silently abandons AC-2/AC-6's degrade guarantee on the slow path.** §5.2/D-4 correctly kills the preflight paradox, but the consequence is that a *down* Starlink lane is only discovered by *spending* a 45-60s timeout per fetch routed to it. With round-robin assigning subs by index to a dead lane, you pay the full timeout × (subs on that lane) before "mark lane down for the run." That interacts with B-1: a dead proxy doesn't just degrade quietly — it can consume the entire Reddit time box in timeouts, which is the AbortController-fires scenario again. AC-6 says "lane-down dry-run logs the fallback, brief unaffected" but never specifies the per-fetch *timeout* on a proxied lane. Required: a bounded per-fetch timeout on the SOCKS lane (R2 mentions "~2s" but R2 is about a preflight D-4 deleted — the live-fetch path has no stated timeout) and a test that a *black-hole* proxy (connects, never responds) degrades within the time box, not just a *refused* proxy.

## Required Changes

1. **Close the wall-clock arithmetic (B-1):** state lane concurrency, give the Reddit gather step a hard per-source timeout decoupled from the global AbortController, and record a real 6-source dry-run wall-clock as a G1 *precondition*, not a post-hoc AC.
2. **Bound the proxied-fetch timeout (B-2):** specify the per-fetch timeout on a SOCKS lane and add a black-hole-proxy (not just refused) adversarial test to AC-6.
3. **D-2b's "absolute floor TBD" is a hole in the only real gate.** The canary (D-2) is explicitly "the real gate," and it requires a high-volume day, but "high-volume" is "75th percentile of observed window (or absolute floor TBD)." A TBD in the gate definition means the gate can be satisfied by a quiet week's 75th percentile. Pin the absolute floor from Phase-1 perf data *before* G3 can fire (make it an explicit G3 precondition, not a parenthetical).
4. **AC-15 says ~5/9 subs over a ≤2-day rotation; D-5's silent-block is N=3 consecutive zero-days.** A sub on a 2-day rotation is *expected* to be fetched==0 on its off-day. The watchdog reads per-source aggregate (reddit total), not per-sub, so this is probably fine — but the PRD never states the watchdog keys on *aggregate* reddit fetched, not per-sub. Make D-5/AC-5 explicit: zero-streak is on the *source* total, and a rotating-subset off-day for an individual sub is not a zero-day. Otherwise the rotation (AC-15) and the watchdog (AC-5) are on a collision course.
5. **Canary baseline is undefined (D-2/§5.4).** "diff posted set vs the un-wired baseline" — the baseline is *the same day's* un-wired run, but you only get one real brief/day and wiring is a prompt edit. Specify how the baseline is produced: a `--no-output-features` dry-run of the *same* candidate pool on canary day, captured immediately before the wired run, so the diff is apples-to-apples and not yesterday-vs-today.

## Lens Notes (one line each)

- **Architecture:** Sound phasing (gatherers before output features, §D-3); the prompt-block-as-program model is the real risk surface and §D-8's exit-code capture correctly addresses the one place a TS throw doesn't auto-degrade.
- **Security/identity-isolation:** Clean — no new creds (§7), gatherers credential-free, honest-zero engagement enforced as an invariant (§3); no injection surface added since gatherer text already flows through the existing scorer.
- **DevOps/SRE:** Rollback is genuinely one-command-per-phase (§11) and gates are real; the launch contract's weak point is the unproven wall-clock budget (B-1), not the rollback path.
- **Implementation/maintainability:** Reusing the real modules in the shadow harness (not reimplementations) and per-source seen-lists (§D-4b) are correct; the prompt.md-as-config gate convention is consistently applied.
- **QA:** Tests are mostly real acceptance gates (forced-failure degrade, double-post short-circuit, forced-module-throw, stale/malformed watchdog inputs) — the gap is wall-clock/timeout behavior (B-1/B-2), which no test currently exercises.
- **Config-drift:** Strong — every config-class edit is diff+`.bak`+approval (§3), the rotating-subset selector is deterministic/version-controlled, and D-9 closes the watchdog-can't-report-its-own-death loop via the obs stack.

## Residual Risks / Open Questions

- **The shadow harness provably can't model live pool-replacement** (stated honestly in D-2), so the *entire* output-feature safety case rests on a single canary run. One clean canary is N=1; consider a 2-3 run canary window before "leave on," since a single quiet day's pool may not trigger the dedup/MMR paths that the shadow couldn't model.
- **AC-15 rotation means any single sub is sampled every ~2 days** — a fast-moving sub (r/LocalLLaMA) will systematically miss ~half its hot items. That's a *quality* regression vs. fetching it daily, masked as a budget win. Acceptable, but it should be a stated trade-off, not silent.
- **github-trending is "general trending, not AI-filtered" (§5.2)** flowing through the existing scorer — confirm the scorer actually down-ranks a trending Rust CLI or a JS framework, or Phase 1 injects off-topic noise into a load-bearing AI digest. No evidence in the pack that the scorer was tested against general-trending input.
- **N=3 zero-days for silent-block (OQ-2) is 3 days of a blind digest before anyone knows** — for a load-bearing daily, consider N=2, or a softer `#logs` note at N=1.
- **Reddit RSS as the sole read path is one ToS-tightening away from dead** (the API already died once here, per AGENTS.md); no fallback source for the Reddit lane is in scope, which is fine for now but is the single largest source-availability risk.
