## Required Changes

**1. De-fang B.2a/B.3's "cleanly separates" claim — substring markers over-fire on genuine AI repos (B.2a, B.3, §3, §4).**
B.2a matches markers as "case-insensitive **substrings** of the description." I stress-tested this against adversarial on-topic descriptions and it false-floors real AI/dev content:
- `"an AI agent that scrapes IPTV metadata for ML training"` → floored on `iptv`
- `"LLM coding-interview prep assistant"` → floored on `interview`
- `"RAG over a study-plan curriculum generator using GPT"` → floored on `curriculum`
- `"a live-chat support agent powered by an LLM"` → floored on `live-chat`
- `"Tesla-stock LLM forecaster, a financial foundation model"` → floored on `tesla`

This is **fail-safe in direction** (false-negative, not a false-positive — these get excluded, never rescued), so it is NOT a blocker. But B.3 and §3 assert the markers "cleanly separate … all genuine AI/dev repos stay ON." That's only true for *today's 18 rows*. The spec must (a) downgrade the claim from "cleanly separates" to "cleanly separates on the live pool; substring markers are intentionally aggressive and accept some on-topic false-floors as the safe direction," and (b) add a `_breakdown` provenance for `offtopic_repo_marker` (already in §4 — good) so the post-cutover audit can *measure* the false-floor rate. Do not write "all genuine AI/dev repos stay ON" into acceptance as an invariant; it's a one-day ranking artifact, exactly the P1-3 failure mode in a new costume.

**2. Pin the thin-pool probe to assert the marker false-floor is the ONLY exclusion mode, not silent loss (§4 thin-pool probe).**
The thin-pool probe asserts "no off-topic repo clears ALSO_GATE." Good — but with substring markers now aggressive (Required Change 1), the probe should ALSO assert the inverse on the degraded pool: that the known-on-topic recovery set (cua, SkillSpector, Kronos, Agent-Reach, meshery) still clears its gate when X is absent. Otherwise the marker set could pass the probe by over-flooring *everything* github, silently re-introducing the false-negative the whole spec exists to fix — and the probe wouldn't catch it. Add the positive-recovery assertion to the same degraded-pool probe.

**3. State the reddit-vouch residual risk explicitly (A.2, §2).**
The reddit vouch fires on the ZERO-tech-token, NO-marker path and returns `(None, "vouch")` → model label governs. The load-bearing assumption is: *a clean, token-less post in a curated AI sub is always topical-enough.* The counterexample class the spec never names: off-topic-but-clean posts that genuinely occur in AI subs — "what GPU should I buy," hiring threads, mod announcements, sub-drama, meta. None carry an OFF_TOPIC_MARKER, none carry a tech token, so the vouch lets a model `core` label ride. This is an **accepted** design trade (the sub vouches topicality, and it's fail-safe vs. the *politics* guard which is what's load-bearing), but the spec should name it in A.2 as the known residual and record `source_curated_vouch` in `_breakdown` (already specced) so the audit can quantify how often the vouch carried a non-topical post. Make the accepted risk explicit rather than implicit.

**4. Add the github on-topic repo with a coincidental marker as a named selftest (B.2a, §4).**
§4's marker selftest lists off-topic repos that must floor (iptv/freeCodeCamp/optimizerDuck/music-assistant) and on-topic that must stay ON (cua/SkillSpector/Kronos/meshery) — but none of the "ON" cases contain a marker substring. Add at least one adversarial selftest pinning the *accepted* behavior: a genuinely-on-topic repo whose description contains a marker substring (e.g. an AI-agent repo mentioning "iptv" or "interview") → document that it floors, and that this is the accepted safe-direction cost. This converts the silent over-fire into a tested, intentional decision rather than a production surprise.
