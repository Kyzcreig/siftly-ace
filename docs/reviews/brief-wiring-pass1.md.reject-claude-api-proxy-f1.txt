# Independent Senior Review (Opus)

## Verdict: APPROVE WITH CHANGES

## Critical Blockers (severity-ordered, cite section/evidence)

**B1 — The "≥3 dry-runs prove zero-regression" gate (G1, §5.5/§6 Phase 1) is structurally incapable of proving the invariant it claims to.** §3 Invariant-1 promises "no posted-set regression" and §6 Phase-1's E2E check is *dry-runs of the same day's pool*. A dry-run with the same candidate set, same scorer, same selection floor will not surface the actual regression vector: gatherer candidates **change the competitive field** — they can displace a previously-surfaced X/HN item below the Top/Also gate even when nothing "fails." Three dry-runs on three consecutive days is not an A/B; it's three uncontrolled observations with no baseline held fixed. The shadow harness already built for the output features (`output_shadow.ts`, offline read-only over real run dumps) is *exactly* the missing instrument for gatherers, yet D-3/§5.5 explicitly exempts gatherers from a shadow window. **Require a gatherer shadow run (candidates injected into the pool, scored, selected, but NOT posted, diffed against the real posted set) before G1 go-live — same discipline the project already imposed on every other output-changing change.** Adding candidates to the pool IS an output-changing change; the PRD's own D-3 rationale ("adding a source is lower blast radius") is the assumption that needs testing, not asserting.

**B2 — Lane preflight (D-4/§5.2/R2) introduces a fresh empty-digest / hang vector into the load-bearing path, contradicting Invariant-1.** A ~2s SOCKS reachability check (R2) runs *inside the brief's gather step*, in the prompt-driven shell. If the preflight itself hangs (proxy half-open, TCP accept but no data — the classic SOCKS failure mode a 2s connect-timeout does NOT cover), or the `tsx` gatherer invocation hangs on a slow lane past the cron's wall budget, the brief is now coupled to Starlink uptime. The PRD says "never block the brief on the proxy" but specifies no hard per-gather timeout, no overall gather-step budget, and no proof the `tsx scripts/gather/reddit.ts` call is bounded. **Require: an explicit hard timeout on the entire reddit gather sub-step (connect AND read AND total-wall), default-direct-lane-on-any-timeout, and a forced-hang (not just forced-fail) dry-run in the G1 evidence.** "Bad lane + bad direct" (§6 Phase-1 negative test) tests *refusal*, not *hang* — the dangerous case is untested.

**B3 — The silent-block watchdog (D-5/§5.3) reads gatherer-probe artifacts, but after Phase 1 the live brief writes a DIFFERENT artifact (perf-log source counts), and the probe cron (`gatherer_probe.ts`) is a separate inflow path.** §7 says the brief logs `raw_reddit`/`sources_reddit` to `digest-perf.jsonl`; §5.3 says the watchdog reads `~/.hermes/state/x-bookmarks/gatherer-probe/`. Those are two different reddit-fetch surfaces with two different lane/IP/timing profiles. A silent block on the **brief's** reddit fetch (the one that matters) could be invisible to a watchdog watching the **probe's** fetch (different IP rotation, different schedule), and vice-versa. **The silent-block watch must read the live brief's own reddit fetch result, not a sibling probe's.** As specified, AC-5 can be "green" while the actual brief has been silently Reddit-blocked for a week.

## Required Changes

1. **Add a gatherer shadow phase before G1** (fixes B1): inject gatherer candidates into the real scored pool offline, diff the resulting Top/Also set against the actually-posted set across ≥3 real run dumps, report displacements. Reuse `output_shadow.ts` machinery. Make AC-1/AC-2 assert *no net-negative displacement*, not merely "candidates appear."
2. **Bound the gather sub-step hard** (fixes B2): per-lane connect+read+total timeout, overall reddit-gather wall cap, forced-**hang** test in G1 evidence (not just forced-fail). State the numbers (e.g. connect 2s / read 5s / total 12s) in §5.2, not "fast (~2s)".
3. **Point the silent-block watch at the brief's own fetch result** (fixes B3), or unify the brief and probe onto one recorded reddit-fetch artifact. Reconcile §5.3's source with §7's `digest-perf.jsonl`.
4. **Specify the dedupe merge-key collision behavior** (§3 Invariant-4, §5.2). Reddit/github candidates dedupe "against the seen-list" — by what key? URL? Reddit RSS permalinks vs. crossposts vs. the linked article URL (HN already links the same arxiv/github URL) will collide or fail to collide. Define the key and add a cross-source same-URL test (a github-trending repo that's also an HN front-page item is the obvious case).
5. **Define gatherer candidate volume caps** (R1) numerically. "Small curated sub list" + "AutoMod sticky filter if needed" is a TODO, not a control. State max candidates/source into the pool so a hot-drama day can't flood scoring.
6. **OQ-2 (N=3 silent-block) interacts with R4** (≈1 fetch/window/IP): if lane round-robin means a given sub is only attempted every few days, N=3 *consecutive zero-days* may be normal, not a block. Define "zero-day" against attempts, not calendar days.

## Lens Notes (one line each)

- **Architecture:** Sound phasing and blast-radius ordering, but D-3's "adding a source is low-risk" is an untested premise treated as a decision (B1).
- **Security/identity-isolation:** Clean — no new creds, no token surface; SOCKS lane is the only external dependency and it's read-only public RSS (acceptable).
- **DevOps/SRE:** Rollback is genuinely one-command per phase (✓); launch contract weakened by unbounded gather sub-step (B2) and probe/brief artifact mismatch (B3).
- **Implementation/maintainability:** Wiring gatherers into a 43.9K prompt-driven shell block (not into `select_digest.py`) keeps logic in the least-testable layer; prefer moving gather-merge into a tested script over more prompt shell.
- **QA:** Tests are real *failure-mode* gates (forced-fail, double-run) but miss the two cases that actually bite — competitive displacement (B1) and hang-not-fail (B2); dry-runs ≠ A/B.
- **Config-drift:** G1/G2/G3 diff+`.bak`+approval discipline is strong and consistent with project precedent (✓).

## Residual Risks / Open Questions

- **Honest-zero engagement vs. low-reach cap interaction (unaddressed):** prior work added a `low_reach_cap` that caps non-thought-leader X items with <5 engagement at 70 (below Also). Reddit RSS candidates are *honest-zero by construction* (§3 Invariant-4). Does `low_reach_cap` apply to them? If yes, **every Reddit candidate is structurally capped below the Also gate and can never surface** — making Phase 1 a no-op that "passes" AC-1 (candidates appear in pool) while never reaching the post. This is the single most likely "it shipped and does nothing" outcome and is not mentioned anywhere. Resolve before G1.
- **score_digest.py label model on non-X bodies:** deterministic scoring infers content_type/on_topic from text tokens; Reddit titles + github repo descriptions are a different distribution than tweets/HN. Will need its own label-trust backstop calibration; not scoped here.
- **Cross-brief dedup (Phase 3) spans morning-digest + x-feed but x-feed gather is explicitly unchanged (§2):** confirm the provenance DB schema already keys both briefs, or Phase 3 dedup is one-directional.
- **OQ-3 lean (both gatherers) doubles the new failure surface at G1** — consider github-trending-only first (the reliable source), Reddit second, to isolate the riskier lane/proxy path.
- **No mention of what happens to `wave6-output-shadow-watch` after G3 go-live** — does it keep running as a regression sentinel, or is it decommissioned? A post-go-live silent sentinel is cheap insurance.
