# PRD v12 DRY Consolidation — Senior Review (Pass 1)

## Verdict
**BLOCK**

The intent is sound and the D9 behavioral change is handled correctly (fenced, guarded, invariant-backed — prd-plan's own "smuggling" pitfall is satisfied). But the verification spine — the grep-based acceptance checks that are the *entire* objective proof of "it's actually DRY now" — is built on canonical phrases that **don't match ground truth**. As written, the headline acceptance grep (§10) matches **zero** files today, several Phase checks are non-discriminating, and §1.1's "verbatim duplicate copies" premise is **factually false** against the live skills. This passes its own gate while duplicates survive. That's the exact failure mode the review is meant to catch.

## Critical Blockers

1. **§10 / Phase 2 — the headline acceptance grep matches ZERO files today; it's an invented phrase.**
   *Premise being tested:* "the dual-format rule is currently a verbatim string `every saved file → Markdown` living in 3 skills, and after Phase 2 it lives in only prd-share."
   *Observed fact (grep, 2026-06-10):* `grep -rl "every saved file → Markdown" prd-*/SKILL.md` → **zero hits**. The arrow-form string exists nowhere. The actual live strings are `every saved file gets Markdown` (prd-document only) and `user chat gets HTML; everywhere else gets Markdown` (prd-plan). *Why it blocks:* an acceptance check that greps a phrase present in zero files **passes trivially and proves nothing** — it returns "only prd-share" (or zero) regardless of whether duplicates survive. The single-source proof is non-discriminating at the source.

2. **§1.1 / §4.2 — the "3 verbatim hand-synced copies" premise is false; the copies are already differently-worded, and one of them is already a pointer.**
   *Premise:* dual-format delivery is "3 hand-synced copies," canonical home "none."
   *Observed fact:* prd-plan says "user chat gets HTML; everywhere else gets Markdown. No exceptions." prd-document says "User chat gets HTML; every saved file gets Markdown. No exceptions." **prd-closeout does NOT carry a third full copy** — its only dual-format text is a *relationship-note clause* that already attributes ownership to prd-document ("prd-document owns … the dual-format rule … invoke that procedure rather than re-encoding it"). *Why it blocks:* (a) §4.2 instructs "collapse prd-closeout's *Dual-format rule section* to a pointer" — there is no such section; closeout already points. The edit described doesn't exist. (b) "Move the full text from prd-plan, verbatim" (§4.2, Phase 1) is ambiguous: prd-plan and prd-document are worded *differently today*, so "verbatim" has no single referent — the build will silently pick one wording and call it canonical, which is a content decision masquerading as a relocation. The "drift already happened" claim in §1.1 footnote 1 is real evidence that these are NOT verbatim — which directly contradicts the table's "hand-synced copies" framing two rows up.

3. **Phase 3 — the lifecycle-diagram grep cannot prove all 5 diagrams collapsed, because there is no single canonical diagram string; there are 5 different ones.**
   *Premise:* "the full diagram phrase `prd-plan → prd-review-pipeline` / `interview…author…review…closeout` returns zero after Phase 3."
   *Observed fact:* the 5 diagrams are materially different strings:
   - interview: `prd-interview → prd-plan → … → build → prd-closeout`
   - plan: `prd-plan → … → build → prd-closeout` (no harden)
   - closeout: `prd-plan → … → build → prd-harden → prd-closeout`
   - harden: `prd-plan → prd-review-pipeline → swarm/plan → build → prd-harden → prd-closeout` (abbreviated)
   - swarm-plan-review: `prd-plan → … → prd-swarm-planner(plan) → prd-swarm-plan-review → … → prd-closeout`
   *Why it blocks:* (a) a grep for `prd-plan → prd-review-pipeline` will **still hit the per-skill local upstream/downstream neighbor pointers** that §4.3/§4.5 explicitly say *stay inline* — so the check can never legitimately return zero, OR it false-fails the build. (b) No single phrase covers all 5, so "returns zero" can be satisfied while 2–3 hand-drawn variants survive untouched. The check is simultaneously over-broad (catches the pointers that must stay) and under-broad (misses variant wording). It does not discriminate a partial consolidation.

4. **D7 / Phase 6 "7-way grep table" — the canonical phrases are unspecified and, where specified, wrong; the load-bearing verification mechanism is undefined.**
   *Premise:* "each of 7 concerns resolves to exactly one canonical location via a grep for its canonical phrase."
   *Observed fact:* only 2 of the 7 phrases are concretely named in the PRD (§10), and one of those (`every saved file → Markdown`) matches zero files. The other 5 (doc-share mechanics, Obsidian Portability, verification-block schema, Constitution/Invariants format) have **no named grep string anywhere in the PRD**. *Why it blocks:* the single most important deliverable — "the 7-way grep table all-green" — has no defined inputs. You cannot run it, cannot tell if it's discriminating, and "exactly one owner" is unfalsifiable until each of the 7 strings is pinned to a phrase that (i) exists verbatim in exactly the intended owner today and (ii) does NOT appear in the legitimately-retained pointers/relationship-notes.

## Required Changes

1. **Replace every invented grep phrase with a verified, ground-truth string — and prove each one is discriminating before the build.** For each of the 7 concerns, add to the PRD a *pinned canonical phrase* chosen by this procedure: `grep -rn "<phrase>" prd-*/SKILL.md` today returns the exact set of current duplicators (not zero, not a superset). E.g. for dual-format, pick `everywhere else gets Markdown` or `every saved file gets Markdown` — whichever you designate canonical — and show its current hit set. Kill `every saved file → Markdown` (zero hits = dead check).

2. **Fix §1.1 and §4.2 to match reality: drop the "verbatim 3 copies" claim, name prd-closeout as already-a-pointer, and make "canonical wording" an explicit decision, not "verbatim."** Add a Resolved Decision: *"Canonical dual-format wording = prd-plan's current text (or prd-document's — pick one and quote it in the PRD); the other two are reworded to pointers. This is a content-normalization step, acknowledged, because the copies were NOT identical."* Remove the §4.2 instruction to collapse a non-existent "prd-closeout Dual-format rule section"; replace with "prd-closeout already points to prd-document for dual-format — leave it, or re-target the pointer to prd-share if prd-share becomes the owner (note the two-hop)."

3. **Resolve the dual-format ownership contradiction (prd-share vs prd-document) — it's currently a two-hop pointer chain.** D3/§4.2 move the canonical rule to **prd-share**. But prd-document's whole identity (its description + body) is "single source of truth for how we document … owns the dual-format rule," and prd-closeout points to *prd-document* for it. After Phase 2, prd-closeout → prd-document → prd-share is a **2-hop pointer**, violating D8 ("one click away, not two"). Decide: either (a) keep dual-format canonical in **prd-document** (it already owns documentation + already is the pointer target) and have prd-share point *to it*, or (b) move to prd-share and re-target prd-document's and prd-closeout's pointers in the same phase so no 2-hop survives. The PRD must pick one and update D3, §4.2, and prd-document's skill description accordingly.

4. **Make Phase 3's lifecycle grep discriminating: grep for a sentinel that ONLY the full diagram contains, and that the retained neighbor pointers do NOT.** The 5 diagrams share no clean phrase but the local pointers are short ("Immediately upstream: X"). Define the canonical diagram in `lifecycle.md` to contain a unique sentinel token (e.g. a comment line `<!-- canonical-lifecycle -->` or the full `interview → plan → review → plan-review → load → run → harden → closeout` 8-stage chain that no current variant matches), then the check is `grep -rl "<sentinel>" prd-*/SKILL.md` → zero (sentinel lives only in the ref file). Separately assert each of the 5 still contains its one-line neighbor pointer (positive check). Also reconcile: the 5 current diagrams disagree on whether **harden** is even in the lifecycle (plan/interview omit it; closeout/harden include it) — the new canonical diagram silently resolves that disagreement, which is a *content* change the PRD calls "verbatim." Call it out.

5. **Add a "no 2-hop pointers" acceptance criterion and a "no pointer survives as a hidden duplicate" negative check.** D8 promises "one hop." Add: for each consolidated concern, the pointer target is itself the canonical home (not another pointer). Mechanical check: the file each pointer names must be the file where the canonical phrase grep hits — assert pointer-target == grep-owner.

6. **Phase 1 negative check is wrong-direction.** `grep -c "chat=HTML\|dual-format" prd-share/SKILL.md ≥1` greps for `chat=HTML` (a string that appears in none of the skills) and `dual-format` (which appears in prd-closeout/document, not prd-share, today). It will read 0 before the edit and only pass if the *new* section happens to use the token `dual-format`. Replace with: after adding the section, `grep -q "<pinned canonical phrase>" prd-share/SKILL.md` returns 1 — using the *same* pinned phrase Phase 2 later proves is unique.
