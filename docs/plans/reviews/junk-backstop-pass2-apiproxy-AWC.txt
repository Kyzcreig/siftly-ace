# Independent Senior Review (Opus)

## Verdict: APPROVE WITH CHANGES

v2 genuinely resolves all four pass-1 blockers — the holdout gate, the monotonic clamp, the all-234 byte-stability redefinition, and the field contract are real fixes, not paper ones. What remains are construction gaps inside those fixes (a clamp that doesn't actually bound post-PF, an oracle-independence claim that Argus can't fully discharge, and a holdout that shares the author's blind spot). None is a tautological-green of the pass-1 class; all are tightenable pre-build. Fix the DEMOTE_CEILING arithmetic and the holdout-independence gap, then build.

## Critical Blockers (severity-ordered, cite section/evidence)

**B-1 — `DEMOTE_CEILING = ALSO_GATE − PF_CAP − 1` does not actually bound the post-PF score, because PF is not the only post-clamp additive term (§5.2, D-3, AC-1).** The clamp is applied to `final` *before* the comment in §5.2 says "cannot be re-lifted by PF" — but the spec itself lists **"any author/recency/media term"** as also landing on the demoted item (§5.2 prose, R-4). If those terms are added *after* the clamp, the ceiling math only subtracts `PF_CAP`, not `PF_CAP + author + recency + media`, and a demoted item can re-cross ALSO_GATE. Conversely, if every additive term (PF included) is applied *before* the clamp, then the clamp should simply be `DEMOTE_CEILING < ALSO_GATE` and the `− PF_CAP − 1` is wrong/misleading. The spec can't have it both ways. **Required: pin the exact arithmetic order — clamp must be the LAST operation after every additive term (PF, author, recency, media), in which case `DEMOTE_CEILING = ALSO_GATE − 1` suffices and is provably below-gate; OR if PF is applied post-clamp, subtract the full post-clamp additive envelope, not just PF_CAP. AC-1 must assert the clamp is literally the final write to `final`, with a selftest that adds max PF+author+recency+media to a demoted item and shows it still `< ALSO_GATE`.** Also pin whether ALSO_GATE is inclusive (`>=`) — a clamped item landing *exactly* on the gate passes if inclusive.

**B-2 — INV-2b's "independent" oracle is not independent enough to discharge B-1-pass-1 (§3 INV-2b, §6 Phase 0, R-5).** The pass-1 blocker was train==test. v2's two-part fix is (a) a held-out 2nd day and (b) Argus as independent labeler. But: the holdout is selected, captured, and near-miss-seeded **by the same author who wrote the regexes**, and Argus labels only "the seed-11 + near-miss set" — i.e. the items the author already suspects — **not the full holdout pool**. The actual precision gate (INV-2: demoted∩non-junk=∅ on the holdout) runs against the *author's* full-holdout labels, which Argus never independently verified. So the holdout's clean/junk boundary — the exact thing a false demotion hides behind — rests on single-author labeling, the same failure mode pass-1 flagged. **Required: Argus (or a second independent pass) labels the FULL holdout pool, not just the author's pre-flagged subset; the precision gate compares B4's demotions against the *reconciled independent* holdout labels. If Argus only sees pre-flagged items, it can only confirm true positives — it is structurally blind to the false positives the gate exists to catch.**

## Required Changes

- **Holdout is still one author's curation (B-2 corollary, R-1/R-5):** the 2nd day is better than same-day, but both days are chosen by the author and the near-miss set is hand-seeded. State explicitly that the holdout's *clean* set (the FP-exposure surface) is independently labeled, and report holdout **size + base rate** — a holdout with 2 junk items and no near-misses proves nothing even at precision 1.0.

- **`_promo_lowers(ct, ac)` construction proof is per-pool, reintroducing the pass-1 B-2 hazard in miniature (§5.2, INV-1).** INV-1 now correctly clamps, so promo-as-upgrade can't raise the *final* — good. But `if _promo_lowers(ct,ac): ct="promo"` still mutates `ct` before the arithmetic, and the INV-1 closeout only asserts `BASE["promo"][ac] == min over content_types` as a *fact to check*, not enforced by construction. Since the clamp already guarantees the outcome, **drop the `promo` route entirely (Open-Q1's own fallback) unless you can show a concrete item where clamp-alone leaves it ≥ ALSO_GATE.** Belt-and-suspenders that adds a mutation path is net-negative here; the clamp is the whole guarantee.

- **AC-3 byte-stability vs. the clamp's own pool effect (INV-5, R-4):** the proof re-runs PF mean / author-cap / overview before+after and asserts no non-junk slot change. But demoting 11 items *will* change `pool_mean_embed` (fused PF centers on it) and author-cap counts — so a non-junk item's *final_score* can legitimately move even though B4 never touched it. INV-5 says "byte-identical final_score." Pin which it is: **either** the fused-PF centering delta is provably below display/round precision (show the actual ppm), **or** INV-5 is scoped to "no non-junk item changes *slot/selection*" and byte-identical is dropped for the PF-affected field. As written, AC-3 may fail on correct behavior — the exact pass-1 B-3 defect, reintroduced via the pool-mean coupling.

- **Foreign-clickbait `JUNK_ASCII_MIN` boundary (D-4, §5.1.4):** the constant is named and emoji-excluded — good — but the near-miss list (Phase 0) still doesn't name a **Latin-diacritic** adversarial row (Vietnamese/Turkish/Indonesian AI post: high non-ASCII-byte ratio under a naive measure, genuinely on-topic, Latin script). Add it explicitly; "non-Latin-dominant" must be measured by script class, not byte-ASCII ratio, or a Turkish LLM post trips it.

- **Phase 5 / AC-8 "≥1 firing" can be satisfied by a near-miss, not an incident (§6 Phase 5, AC-8):** "debug dump shows ≥1 `junk_backstop` firing" proves the layer *executed*, but if the prompt now labels the real junk `off` first (R-3, defense-in-depth working), the only thing left for B4 to fire on could be borderline. Strengthen: the live proof must show B4 firing on an item the model labeled `core` (the actual mislabel class), not merely any firing — otherwise R-3 ("prompt agrees → signal vanishes") isn't actually closed.

## Residual Risks / Open Questions

- **Holdout base rate is the silent foundation:** precision 1.0 on a holdout with no near-misses and 2 junk items is worthless; the gate's strength is entirely the holdout's FP-exposure, which the spec doesn't quantify — report size, junk count, and near-miss count or the gate is decorative.
- **Two ratified days, adversarial shapes (R-2):** correctly scoped to v1 + committed monthly re-eval — acceptable, but the demotion-rate watchdog baseline (`JUNK_DEMOTE_ALERT_N`) is unstated; a too-high threshold makes the LOUD guard silent.
- **Oracle remains contestable by fiat (R-5):** "$COIN U.S." vs a real AI-equity post — Argus reconciliation helps, but only if Argus labels the contested item independently, not just confirms the author's seed; same root as B-2.
- **`promo` removal is the cleanest INV-1 close:** if you can't produce a clamp-alone-insufficient item, the `promo` path is pure risk surface — recommend deleting it before build rather than carrying `_promo_lowers` and its per-pool assertion.
