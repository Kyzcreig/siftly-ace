# PRD — greenhouse.ace portal migration onto the shared `card_grid` module

**Status:** ✅ SHIPPED 2026-07-05 (greenhouse.ace live on the module; sort dropdown added per Ace). **Owner:** Apollo. **Date:** 2026-07-04
**Depends on:** `card_grid.py` (shipped this session; docs.ace = consumer #1).
**Theme decision (Ace, 2026-07-04):** greenhouse **keeps `github-dark`** — do NOT flip it to noir.

## 1. Why
greenhouse.ace and docs.ace are the same UI class — a searchable grid of cards — and were
independently hand-rolled (greenhouse: `greenhouse_portal.py` `render()`, ~406 lines of bespoke
CSS+JS; docs.ace: now on the shared module). We extracted `card_grid.py` (sibling of
`dashboard-table-builder`) and moved docs.ace onto it. This PRD moves greenhouse onto the same
module so both card-grid portals share ONE renderer — the index.ace/logs.ace consolidation pattern,
applied to the card-grid family. Net effect: greenhouse's render code drops from ~406 lines to a
~40-line spec builder; future card-grid improvements (a11y, mobile, new facets) land once.

## 2. Non-goals
- **No visual redesign.** greenhouse stays github-dark and must look ~identical after migration
  (this is a refactor, not a restyle). Any pixel drift is a regression to fix, not a feature.
- **No behavior change** to the greenhouse pipeline/collector/signals — only the PORTAL RENDER.
- **No new features** beyond reaching parity (the status filter, search, per-card signal all keep working).
- docs.ace is untouched.

## 3. What greenhouse's portal renders today (the parity target)
Per-card (`render()` around L229): `data-search` (title+summary+type haystack), `data-status`
(bucket: `accepted|rejected|nothing`), an **icon** by type, a **title**, a colored **status pill**
(`st-accepted` green / `st-rejected` red / `st-nothing` transparent), a **signal emoji** (✅/❌/—),
a **meta** dots line (`●●●○`), a **summary** (≤300 chars). Controls: a search box + a **status
filter** (`all|accepted|rejected|nothing`). Footer: generated-at + last-poll status. Served file:
`~/.hermes/greenhouse/portal/served/index.html`, regenerated by the greenhouse cron/pipeline
launchd jobs; published via `publish()` with a `_privacy_scan()` gate.

## 4. Gap analysis — module today vs. greenhouse needs
| greenhouse element | module support today | action |
|---|---|---|
| search box | ✅ built-in | use it |
| status **filter** (all/accepted/rejected/nothing) | ✅ facet dropdown (`facets:[{id:"status",…}]`) | map bucket → `card.facets.status` |
| **colored status pill** (green/red/neutral, 3 states) | ⚠️ only ONE gold `.badge` style | **ADD**: multi-variant badge (see §5) |
| per-card **signal emoji** (✅/❌/—) | ⚠️ no dedicated slot | render into `card.badges` OR a small `meta` prefix |
| type **icon** | ⚠️ no icon slot | **ADD** optional `card.icon` (emoji, escaped) before title |
| **meta** dots (`●●●○`) + summary | ✅ `card.meta` + (need) a **summary/body line** | **ADD** optional `card.body` (escaped, clamped) |
| footer (generated/last-poll) | ⚠️ module has no footer | **ADD** optional `spec["footer"]` (trusted HTML, esc'd by caller) |
| no per-card action buttons | ✅ actions optional (omit) | omit `card.actions` |

## 5. Required module additions (small, additive, theme-agnostic)
All additive — docs.ace spec doesn't set them, so its render + CSP hash are unaffected **except**
where noted. Keep GRID_JS byte-identical (CSP hash must not drift) — these are markup/CSS only.
1. **`card.icon`** — optional escaped string rendered before the title in `.ctype`/head row.
2. **`card.body`** — optional escaped summary line under the meta (clamp at caller; module escapes).
3. **Multi-variant badge:** `badge = {"text":…, "variant":"ok|warn|bad|neutral"}` → CSS classes
   `.badge.ok/.warn/.bad/.neutral` using theme `--vars` (green/amber/red/muted). Existing
   `{"text":…}` (no variant) stays the gold default → **docs.ace unchanged**. (greenhouse status pill
   + signal emoji both become variant badges.)
4. **`spec["footer"]`** — optional trusted-HTML footer band (caller `esc()`s dynamic bits), matching
   dashboard-table-builder's footer convention.
5. **Verify GRID_JS unchanged** → `grid_js_sha256()` still `qyDG…`; docs.ace CSP untouched. If any JS
   change becomes necessary, docs.ace's CSP hash list must be regenerated in the same change (gate).

## 6. Migration steps (execution phase — NOT this session)
1. Add §5 module features; re-run docs.ace verify (facet+sort+search+actions + CSP) → no regression.
2. Rewrite `greenhouse_portal.py` `render()` to build a `spec` → `render_card_grid(spec)`
   (theme `github-dark`). **Keep the old `render()` as `render_legacy()`** (graceful-import +
   keep-legacy-for-rollback, per `references/dashboard-module-consumer-migration.md`).
3. **Parity gate (CDP, two-oracle):** screenshot old vs new at the same width; assert same card
   count, status-filter still filters (set `status=rejected` → only red cards), search still filters,
   `scrollWidth==clientWidth` (no overflow). Geometry is authoritative for layout (vision false-flags
   alignment — proven on docs.ace this session).
4. Keep `publish()` + `_privacy_scan()` untouched (render swap only).
5. Commit; watch one live greenhouse pipeline regen to confirm the served file renders via the module.

## 7. Risks / mitigations
- **CSP-hash drift breaking docs.ace** (biggest) → §5.5 gate: GRID_JS stays byte-identical; if not,
  regenerate docs.ace CSP in the same commit + re-verify. greenhouse itself has no CSP pin today
  (lower stakes), but don't regress docs.ace.
- **Visual drift** (github-dark parity) → §6.3 old-vs-new screenshot diff before cutover.
- **Contended shared checkout** (skills-shared / greenhouse both live) → land module change first,
  verify docs.ace, THEN greenhouse — never both in one unverified step.
- **Greenhouse pipeline writes the served file on a cron** → do the render-fn swap when no pipeline
  run is mid-flight; the build-guard/cutover-guard jobs already gate that.
